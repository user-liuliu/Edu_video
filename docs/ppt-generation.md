# PPT 生成运行说明

## 入口与生成流程

制作页面的「生成视频 / 生成 PPT」切换到独立路由。PPT 创建 `/presentations/new`，保存后 `/presentations/:id/edit`，大纲 `/presentations/:id/outline`，预览 `/presentations/:id/preview`。我的作品/草稿箱内可筛选 PPT。

项目名称和需求必填，可选参考文件和联网搜索。先保存输入并上传素材，再提交大纲任务；素材在任务中解析。图片或含图片的材料需要配置看图识别模型。解析失败会显示文件名和原因，不会静默忽略该文件。

大纲使用稳定页面 ID，支持 1–40 页，增删排序、手动修改和指定页面模型改写。生成课件绑定已保存的大纲版本；预览内的模型修改只应用所选页面。其他页面的生成内容保留。旧版本保留在服务端有限历史中，本版不提供历史恢复界面。

大纲草稿页先保存修改并核查知识点与公式，再点击「确认大纲」。确认接口只记录当前版本并进入第三步「PPT 预览」，不会创建生成任务或调用模型。预览显示「大纲已确认，课件尚未生成」，教师点击「开始生成 PPT」才提交绑定该版本的生成任务。未确认的版本不能直接生成；修改大纲后需要重新保存、核查和确认。已确认且未修改的大纲可直接重新进入预览。自动页面审核不增加独立页面，重新打开正在制作的大纲会转到预览。

预览显示服务端阶段和总体进度，逐页标记「视觉审核通过」「仍需检查」「等待视觉审核」；没有审核记录的旧课件单独标识。当前接口仅在任务完成后发布逐页结果，因此生成中不展示推测的页级进度，修改中明确展示上一版课件和审核记录。问题包含类别、原因、修改建议及自动修复次数；采用本页建议只选中本页，教师可编辑要求后提交。审核失败可重试；局部修改失败保留上一版预览与下载；预览加载失败可在原页重新加载。

生成与局部修改复用已有「看图识别」模型进行实际导出页面审核；未配置时，大纲页提示配置要求，仍可编辑、保存和确认大纲；实际生成仍由服务端检查审核模型配置。

## 配置与部署

复用管理员的「大纲/讲稿」模型配置；联网搜索仅在配置完成且用户开启时使用。关闭联网不请求搜索。没有新模型配置项。参考文件沿用原平台格式与限制：单文件 25 MiB、每项目最多 10 个、总计 100 MiB。nginx 对视频和 PPT 素材上传均单独允许 26 MiB 请求体，其他接口继续保留原限制。

数据库迁移 `0008_presentations.py` 新增 `ppt_projects`、`ppt_materials`、`ppt_jobs`。任务由独立 Celery 入口和持久化 outbox 执行，scheduler 每 15 秒派发，支持心跳、过期租约回收和逐页检查点。PPT 与视频共用每位教师并发额度，但不共用项目和生成流水线。本版尚未接入 PPT 计费。

在确认将此分支集成到目标部署代码后，保留原 .env、数据库和 MinIO 卷，备份后构建并更新应用与两个隔离渲染服务：

```powershell
docker compose config --quiet
docker compose build backend
docker compose build frontend renderer
docker compose up -d backend worker scheduler renderer ppt-renderer frontend
docker compose exec -T backend alembic current
docker compose exec -T backend alembic check
docker compose exec -T worker celery -A app.jobs.celery_app:celery_app inspect ping --timeout=4
```

PPT 信息图使用独立的 `ppt-renderer` 服务，后端与 worker 通过 `PPT_RENDERER_URL` 连接；视频继续使用原 `renderer`，避免长视频导出阻塞课件预览。两者共用镜像但独立进程、容量与隔离网络。PPT 预览和导出的 nginx 等待上限为 600 秒。

## 模板与导出边界

模板资产位于 `backend/app/presentations/templates/`，来自 ppt-master 作者流程确认的清蓝教学模板，版本 1.0.0。固定 16:9（13⅓ × 7.5 英寸），包含封面、概念、图文、对比、步骤、练习、总结。自动推荐继续默认清蓝；新增两套已批准模板见2026-10-25更新。

运行时内置未经修改的官方 PPT Master 6.7.0 工具包，包含完整来源与许可证，先核验 SHA256 和官方 attribution guard。每次生成从已确认大纲进入 Strategist 设计规划，再由 Executor 绘制 1280×720 页面 SVG；使用官方 project manager、canonical final checker、finalize 和 native exporter。官方角色指导实际进入模型系统提示，设计规划生成 design_spec/spec_lock。没有在运行时下载工具或执行模型生成的代码。

每页必须包含实际可见且尺寸足够的教学矢量图解或参考图片，不能仅用文字卡片充当插图。新页面失败会返回具体原因并重试，不自动降级为文字卡片。固定色板、字体和字号锚点；文字按作者指定分行，导出时关闭自动适应，避免 PowerPoint/LibreOffice 再次拆行。

参考图片来自上传原件，解析后仅在数据库保存素材 ID、chunk 索引、尺寸及 SHA256。预览和导出按当前用户及项目读取私有原件、重新解析并校验摘要。旧素材会重新解析以补齐图片索引。图片规范化为最大 1600 像素边长的 PNG，单张不超过 3 MiB，每次最多 20 张、合计 16 MiB；规范化入口限制解析后图片为 800 万像素静态图。原件解码继续受通用解析器限制，800 万像素不代表原件限制。没有接入 AI 照片生成服务。

SVG 限制为允许的元素和属性，禁止脚本、外部网址、实体、任意路径及跨项目图片。每页最多 180 KB、1200 节点、16 层、16000 路径 token。整个课件通过预览容量、官方检查和实际编译后，才由原有租约及版本检查发布。单页预览不超过 2 MiB、PPTX 不超过 40 MiB；工具超时 90 秒，导出器超时 180 秒。

预览使用同一份作者 SVG，矢量图解导出为原生可编辑 DrawingML，参考图片嵌入 PPTX。下载会根据页面和私有原件重新编译，增加服务端 CPU 开销；数据库事务锁限制整个服务最多两个并行下载导出，同一课件版本不能重复编译，繁忙时返回 429。新课件局部修改保留未选中页面的 SVG 及规划内容。旧版文字模板课件仍可预览和下载，需先重新生成整份图文课件才能使用新版单页修改。

网页内 WPS 式画布编辑、更多模板、版本恢复界面和 PPT 计费为后续范围。

## 测试与验收

后端使用独立 TEST_DATABASE_URL，严禁指向真实库，也不能并行执行两套数据库测试。PPT 专项测试覆盖所有权、版本冲突、幂等提交、选中页隔离、任务恢复、素材解析失败、预览与完整 PPTX 导出以及迁移一致性。前端测试覆盖布局、模式草稿保留、退出清理、保存身份和返回大纲行为。

浏览器检查使用真实 Vue 页面和测试接口数据，覆盖桌面/手机的创建、大纲编辑、逐页预览与下载。七页生物课件由本地测试内容生成整份 PPTX，经 LibreOffice 转 PDF 检查页数和文本边界。没有调用付费模型、联网搜索或修改生产模型配置；真实模型教学质量和 PowerPoint/WPS 中实际编辑需后续从运行服务验收。
