# 第二阶段生成链路优化实施计划

> 按用户授权在当前工作区逐步实现与测试；不提交、不推送、不清理既有修改。使用 executing-plans、systematic-debugging、test-driven-development、verification-before-completion。

**目标：** 素材解析与大纲生成后台串联，进度从后台恢复，部分解析遗漏向教师公开。

**方案：** 复用现有数据库 outbox、parse/generate 任务和租约。提交 generate 时在同一事务中建立解析依赖并占用教师的一个生成名额；等待依赖不占住 worker、不消耗重试次数。前端上传保存后立即提交后台任务并跳转。进度按真实阶段与解析数量保存，模型执行期间用加载动画说明，不伪造逐秒百分比。解析警告独立持久化，不进入知识依据。

**依据：** 用户已授权的前三项优化；原第二阶段计划及最新保存/并发/通知约定。

## 约束与审查重点
- 保存草稿只上传素材，不调用解析/模型；生成时才解析。旧稿在成功前保留。
- 每位教师独享管理员统一配置的并发额度；解析依赖不额外计数。
- 跨用户404、revision校验、租约及原子发布保持有效；进度提交不得提交业务输出。
- 依赖失败、排队、worker恢复、重复提交均能进入明确状态。
- 不读取或输出密钥；测试只用独立数据库及模拟外部服务。
