# PPT Master runtime and teaching visuals

Goal: make ppt-master participate in runtime planning, page design, SVG quality checks and native editable PPTX export. Preserve independent video/PPT flows and the accepted creation UI.

The model follows bundled official Strategist/Executor guidance. First produce a stable-ID page design plan from the confirmed outline, course theme and available reference images; then author each complete 1280x720 SVG with editable text and real native teaching illustrations. Reference raster images remain images; vector diagrams become editable DrawingML. Do not count text in a rectangle as an illustration. Use clear-blue as style anchors, not rigid text slots. There is no configured raster image generation API: do not claim photos are generated.

Vendor the unmodified full official 6.7.0 package in a versioned archive with checksum and attribution. Extract into a private runtime directory; run the official attribution guard. Use the official project manager, canonical final SVG checker, finalize tool and native converter without dangerous export overrides. Generate the audited design_spec/spec_lock pair from a validated structured plan, not arbitrary model markdown. Reject active markup, external URLs, traversal, excessive complexity and references outside the project image allowlist before tools read SVG.

Preserve reference originals in existing private material storage. Index normalized image descriptors (material ID, chunk index, SHA256) in parsed chunks; reparse old ready materials lacking parse_version=2. Image bytes remain in originals, never in database JSON. Resolve only current owner/project materials and re-extract bounded images with digest verification when building preview/export. Store canonical authored SVG and immutable plan per page in existing pages JSON. Compile and validate the entire deck before worker publication; export reconstructs the exact deck through the same pinned runtime. Preview embeds only resolved normalized images into the same authored SVG. No published object keys, no orphan output objects, no runtime downloads. Existing lease/revision fence protects page publication.

Boundaries: SVG namespace only; svg/g/defs/marker/path/rect/circle/ellipse/line/polyline/polygon/text/tspan/image with explicit attribute allowlist; no active markup, foreign namespaces, DTD/entities or CSS URLs. Only controlled image href ../images/<asset-id>.png and internal marker fragments. Max180KB/page,1200nodes,depth16,16000path tokens, finite coordinates within four canvas widths, positive scale<=4, no nested transforms. Teaching visual groups require path or image plus meaningful size; a rectangle/text card is insufficient. Max20images,3MB normalized each,16MB aggregate,8MP parsed image pixels (the general parser bounds original decoding),max1600px edge. Subprocess90sec,exporter180sec,PPTX40MB,preview2MB/page.

Model revision changes only selected page content/SVG; preserve unselected page bytes and plan entries. Compile the entire resulting deck before publication. Outline edits invalidate artifacts. Legacy slot-rendered projects remain readable and downloadable. No fallback to text cards if new design fails: show a retryable actionable error.

Acceptance: official guard and canonical checker execute; exporter produces native text/freeform geometry and embedded reference image; unsafe SVG cannot read files/network or execute code; plans cover exact page IDs; diagram pages have real bounded vector content; selected edits preserve other pages; failed/stale generation preserves published assets; whole PPTX and corresponding previews use the same generated pages. Test a 7-page biology sample and inspect rendered output.

Review refinements: validate actual painted geometry with inherited opacity/transforms, excluding definitions; enforce embedded preview size before publication; stabilize authored line breaks using noAutofit in generated slide XML only. Export compilation uses two global transaction-locked slots and per-project/revision deduplication, retained until subprocess completion even on HTTP cancellation.
