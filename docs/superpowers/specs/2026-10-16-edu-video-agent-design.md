# 教学视频生成 Agent 网站 设计文档

日期：2026-10-16
状态：待确认

## 1. 要做什么、为什么

给中小学老师用的网站。老师用一句想法，或者上传课件、课本再加一段需求描述，告诉 agent 想讲什么。agent 先生成按"段"划分的视频大纲，老师确认或修改后，agent 生成带旁白配音、画面和字幕的讲解视频，最终输出 mp4。

老师做教学视频时，手里常常只有一个想法（比如"讲二次函数"），或者一份现成的课件。这个网站要让老师不用懂剪辑、动画、配音，也能做出可以直接拿到课堂上用的讲解视频。

**严谨是底线。** 这是教学视频，内容错误比做得不好看更严重。

## 2. 使用者与规模

- 第一版：用户自己和身边几位老师试用。老师自己用用户名和密码注册，管理员在后台审核通过后才能使用。
- 以后：很多老师注册使用。数据从第一版起就按"每个老师的数据独立"来设计。
- 两种角色：**老师**（做视频）和**管理员**（管理页面配置、模型配置和用户，同时也能做视频）。

## 3. 目标、非目标、反目标

**目标**
- 两种输入：一句想法；上传课件或课本加需求描述。
- 老师可以选择科目、年级、视频时长、视频尺寸、讲解风格、配音声音，以及是否允许联网搜索。
- 先出大纲，老师确认后再生成视频。
- 老师对视频不满意，可以回到大纲修改；再次生成时只重做改过的段落，没改的段落直接复用。
- 理科：公式、函数图像、几何图形配合动画讲解，风格接近 3Blue1Brown。
- 文科：更生动，用火柴人或简笔画的人物、故事、情景来讲。
- 每段内容都标出依据，老师能核对。
- 最终输出一个 mp4 文件。
- 老师自助注册，管理员审核后才能使用。
- 管理员后台：控制"新建视频"页面上每个选项是否展示、默认值和可选值；管理所有模型和外部服务的配置；管理用户。

**非目标（第一版不做）**
- 手机号或邮箱注册、找回密码（忘记密码由管理员重置）、付费、额度限制。
- 会动的人物动画、视频生成模型、数字人或真人出镜。人物只用静态插图加镜头推拉等简单动效。
- Milvus 向量库、整本教材的检索资料库、跨项目复用的"我的素材库"（第二版再做，届时用 pgvector 或 Milvus 做向量检索）。
- 多人协作编辑、移动端 App、对接学校的教学平台。
- 修改单句旁白时只重配那一句：重新生成的最小单位是"段"。

**反目标（技术上能跑，但出现这些情况就算失败）**
- 老师看完觉得不适合课堂教学：用语和深度不符合年级，风格太花哨或不严肃。
- 公式、函数图像、几何图形出现错误。
- 历史故事、人物、史实没有出处，或者是编出来的。
- 老师关闭了联网搜索，系统却仍然联网。

## 4. 老师的使用流程

1. **新建视频**：填写"想讲什么"，可选上传参考素材，选择各项参数，点"生成大纲"。
2. **agent 生成大纲**：解析素材 → 查找依据 → 按目标时长分段，写出每段的讲稿和画面方案 → 审核 agent 检查一遍。
3. **老师确认或修改大纲**：可以直接改某段的文字，也可以用一句话告诉 agent 怎么改（比如"第 3 段先举投篮的例子"），由 agent 改写对应段落。可以增加、删除段落，调整顺序。
4. **生成视频**：后台逐段生成，网页上显示每段的进度。
5. **预览**：老师在网页上看整段视频，也能单独看某一段。
6. 满意就**下载 mp4**；不满意就回到第 3 步，再生成时只重做改过的段落。

## 5. 新建视频的输入项

| 项目 | 说明 |
|------|------|
| 想讲什么 | 必填，自由文字，可以是一句想法，也可以是详细需求 |
| 参考素材 | 可选，可上传多个文件，支持 PPT/PPTX、PDF、Word、图片（比如拍下来的课本页面） |
| 科目 | 数学、物理、化学、生物、语文、英语、历史、地理、道德与法治等 |
| 年级 | 小学到高中，具体到年级 |
| 教材版本 | 人教版、北师大版、苏教版、沪教版、统编版（语文、历史、道德与法治）等；选项随科目变化，默认人教版或统编版 |
| 视频时长 | 3 / 5 / 10 分钟或自定义；实际时长允许约 ±15% 的偏差 |
| 视频尺寸 | 16:9 横屏（投屏上课用）、9:16 竖屏（手机看）、1:1 |
| 讲解风格 | 默认"按科目自动"，可改成"数学动画"或"故事 / 简笔画" |
| 配音声音 | 从几个豆包音色里选，网页上可以试听 |
| 允许联网搜索 | 开关，默认开启 |

除"想讲什么"外，上面每一项是否展示给老师、默认值是什么、有哪些可选值，都由管理员在后台配置（见第 11 节）。被隐藏的项老师看不到，系统使用管理员设置的默认值。

## 6. 大纲的结构

大纲由若干"段"组成。"段"既是老师修改的单位，也是生成和缓存的单位。每段包含：

- **标题和这一段的教学目标**
- **旁白讲稿**：完整的逐字稿，就是配音要读的文字
- **画面方案**：按旁白的句子排好顺序的画面列表，每个画面是下面几类之一：
  - 插图：火柴人、简笔画、故事场景，写明图片内容
  - 数学图形：函数图像、几何图形、坐标系，以及要做的动画（比如"a 从 2 变到 -2"）
  - 公式：要逐步出现的公式和高亮的部分
  - 学科示意图：受力图、电路图、结构式、实验装置等，注明来源方式（取自素材 / 代码模板 / AI 示意图）
  - 文字卡：要点、标题、小结
- **依据**：这一段每个关键知识点、史实分别来自哪里，见第 7 节
- **内容性质**：是"知识 / 史实"，还是"情景演绎"（为了帮助理解而虚构的场景，会明确标出）
- **审核提示**：审核 agent 发现的问题，在页面上标红显示
- **预计时长**：根据讲稿字数估算

开头一段默认是开场，用来吸引学生，比如旁白"嗨，同学们，今天我们来讲一讲二次函数"，同时抛物线慢慢画出来。最后一段默认是小结。

## 7. 严谨性：依据与审核

**依据来源的优先级**
1. 上传的素材里有依据，就用上传素材，标出文件名和页码或段落。
2. 素材里没有依据、且老师允许联网，就联网搜索，附上来源的标题和链接。
3. 老师关闭了联网搜索：整个流程不发出任何搜索请求。这时如果素材里也找不到依据，agent 只能用大模型自己的知识，并把这条内容标成"未核实出处"，提醒老师核对。

**规则**
- 史实、人物、年代、数据、引用原文，都必须有依据；找不到依据的要标出来，不能把编的内容写成史实。
- 情景演绎可以虚构，但必须标为"情景演绎"，旁白里也不能说成是真事。
- 公式、函数图像、几何图形一律由代码按数学关系计算后画出，不用图片模型画。
- 讲稿的用词和深度要符合所选年级和教材版本：知识点放在哪个年级、用什么术语和讲法，都以所选教材版本为准。

**什么来源算合格依据**
- 优先：老师上传的素材、官方和教育机构网站（如教育部、国家中小学智慧教育平台）、出版社、学术机构、博物馆和权威媒体。
- 百科类网站可以用，但标成"次级来源"，审核时会提醒老师核对。
- 公众号、论坛、问答网站、个人博客不能单独作为史实依据。
- 联网搜到的内容和上传素材（课本、课件）说法不一致时，以上传素材为准，同时在审核提示里写明有分歧。

**审核 agent**
大纲生成后，由一个独立的审核 agent 检查：
- 事实和公式推导是否正确，例题的数值是否算对
- 每条关键内容是否有依据，依据是否真的支持这条内容
- 用语和深度是否适合这个年级和教材版本，有没有超出这个阶段课标的内容
- 情景演绎有没有被说成史实

审核发现的问题以提示的形式挂在对应段落上，由老师决定怎么改。老师修改大纲后，只审核改过的段落。

## 8. 视频生成

每段按下面的顺序生成，各段之间互不依赖，可以并行。

**8.1 配音**
- 使用豆包 `seed-audio-1.0`，接口 `POST https://openspeech.bytedance.com/api/v3/tts/create`，`X-Api-Key` 请求头鉴权。
- 用 `speaker` 参数指定音色（豆包语音合成 2.0 的音色）。
- 开启 `enable_subtitle: true`，拿到句级和字级时间戳，用来对齐画面切换和字幕。
- 单次调用最长 120 秒音频、3000 字。超过的段落按句子拆成几次调用，再把音频和时间戳拼起来。
- 返回的 `url` 只保留 2 小时，所以直接取返回的 base64 音频，立刻存进 MinIO。
- 语速用 `speech_rate` 微调，让总时长接近老师选择的时长。
- 英语课：默认用中文讲解，英文单词、例句用英文读；时长按"中文字数 + 英文词数"分别估算。
- 多音字和古诗文读音：豆包这个接口的文档里没有读音标注参数。审核 agent 会把容易读错的字（比如古诗里的"斜"）列出来提醒老师，老师可以在预览时单独试听这一段的配音。读音纠正的办法等开发时实测后再定。

**8.2 画面**
- **插图**（火柴人、简笔画、故事场景）：用中转站的 gpt-image 模型（`gpt-image-2.5-flare` 或 `gpt-image-2`）生成。图片尺寸按视频尺寸选。
  - 角色一致性：每个视频先生成一张角色参考图（主要人物的样子），之后的插图都把它当参考图传进去。如果中转站不支持传参考图，就退而求其次，在每次的提示词里完整描述角色和画风。
  - 统一画风：同一个视频的所有插图使用同一段画风描述。
  - 插图里不让模型画任何文字，需要的文字（标注、字幕、标题）都由代码叠加上去，避免错别字。
  - 图片检查：每张插图生成后，交给多模态大模型看一遍，检查有没有文字、和画面描述是否相符、人物是否一致、内容是否适合课堂。有问题自动重画一次，仍有问题就在大纲对应的画面旁边标出提醒。
  - 老师对某张图不满意，就修改大纲里这张图的画面描述，再生成时只重画这一张（见 8.4）。
- **数学图形和公式**：用 matplotlib 画，公式用 matplotlib 自带的公式渲染（第一版不装 LaTeX）。
  - 为了准确和稳定，大模型不直接写任意代码，而是输出结构化参数，交给预先写好的几类模板来渲染，比如：函数图像逐步画出、参数变化的动画、几何图形、公式逐项出现并高亮、坐标系上标点。
  - 模板输出的是一小段动画视频片段，或者一张静态图。
  - 以后要做更复杂的动画，再考虑接入 Manim 或让大模型写代码。
- **其他学科的示意图**（物理的受力图、电路图、光路图，化学的结构式和实验装置，生物的细胞结构，地理的地图等），按下面的顺序选择来源：
  1. 老师上传的素材里有对应的图，直接用素材里的图（从 PPT、PDF、Word 中提取图片，或截取页面区域）。
  2. 素材里没有，就用代码模板画。第一版的模板至少覆盖：物理受力图、简单电路图、光路图、运动图像（如 v-t 图）；化学结构式（可用 RDKit 这类化学库生成）、化学方程式。具体种类由开发者按工作量取舍。
  3. 代码模板画不了的，用 gpt-image 画，画面上标"示意图"，并且必须经过图片检查和审核 agent 的检查，检查结果在大纲里提示老师。
  - 地图类：AI 画的地图只能是不带国界、不带具体地名的示意图，需要准确地图时提醒老师上传标准地图。
- **文字卡**：用模板渲染成图片。
- 所有画面里的中文用同一套中文字体，字体文件放进 Docker 镜像。
- **数量和等待时间**（先这样定，试用后再调整）：每段 3 到 6 个画面；5 分钟的视频 AI 插图控制在 20 张左右，10 分钟的控制在 40 张左右；5 分钟视频的生成时间目标是 10 到 20 分钟。每段画面数和插图上限做成配置项，方便以后调。

**8.3 合成**
- 用 FFmpeg 合成：静态图片加上镜头推拉、平移、淡入淡出等动效；按时间戳在旁白读到对应句子时切换画面；字幕按字级时间戳生成，烧进画面里；再配上这一段的音频，合成为这一段的短片。
- 所有段的短片按顺序拼成完整 mp4，段与段之间加简短转场。
- 输出 H.264 + AAC 的 mp4，横屏 1920×1080，竖屏 1080×1920，方形 1080×1080。

**8.4 只重做改过的段落**
- 每段根据"会影响这一段结果的内容"算一个指纹：旁白讲稿、画面方案、配音声音、视频尺寸、讲解风格、年级。
- 再次生成时，指纹没变的段直接复用已有的短片，指纹变了的段才重新生成，最后重新拼接整个视频。
- 更细一层：同一段里，如果只有画面方案改了、旁白没改，就复用原来的配音；只有旁白改了，复用没受影响的图片。
- 大纲生成后能改的全局参数分两类：
  - **只影响渲染**：视频尺寸、配音声音。在大纲页可以直接改，改后受影响的段全部重新渲染，讲稿不变；网页上先提醒老师。
  - **影响内容**：科目、年级、教材版本、讲解风格、时长、联网开关、参考素材。改这些等于重新出大纲：网页提醒"会重新生成大纲，你手动改过的内容会丢失"，老师确认后从头生成大纲并重新审核。
- 版本：每点一次"生成视频"就保存一个版本，包括当时的大纲和生成的视频，全部保留。老师可以看历史版本的视频，也可以把大纲恢复到某个历史版本再继续改。"只重做改过的段"总是和最近一次成功生成的版本比较。存储清理第一版不做。

## 9. 技术方案

| 部分 | 选择 |
|------|------|
| 后端 | Python + FastAPI |
| Agent 流程 | LangGraph（大纲生成 → 暂停等老师确认 → 继续生成；用它的中断和恢复功能），LangChain 用于模型调用 |
| 后台任务 | Celery，Redis 做消息队列；生成进度通过 Redis 推给网页（WebSocket 或 SSE） |
| 数据库 | PostgreSQL：老师账号、视频项目、大纲、段落、版本、生成任务状态 |
| 文件存储 | MinIO：上传的素材、图片、音频、段落短片、最终 mp4 |
| 大模型 | 中转站的 key，接口按 OpenAI 兼容格式调用；用于理解素材、写大纲和讲稿、改写、审核 |
| Embedding | qwen3.7-text-embedding-flash；第一版只在素材很长、需要挑出相关片段时使用，向量先存在内存或 PostgreSQL（pgvector） |
| 图片生成 | 中转站的 gpt-image-2.5-flare / gpt-image-2 |
| 配音 | 豆包 seed-audio-1.0 |
| 画图 | matplotlib；化学结构式可用 RDKit |
| 合成 | FFmpeg |
| 素材解析 | PPTX：python-pptx；PDF：PyMuPDF；Word：python-docx；图片和扫描页：交给多模态大模型识别 |
| 联网搜索 | 可替换的搜索接口，默认接一个中文搜索结果较好的服务（具体由开发时决定，需要一个 API key） |
| 前端 | Vue 3，界面设计按 Anthropic 官方 frontend-design skill 的方法来做 |
| 部署 | Docker Compose：PostgreSQL、Redis、MinIO、后端、Celery worker、前端全部放进去，本地跑通后整体搬到服务器 |

**配置与密钥**
- 模型和外部服务的配置（中转站、Embedding、豆包、搜索服务的地址、key、模型名）由管理员在后台维护，存在数据库里。key 用主密钥加密后存储，页面和接口返回时只显示末尾 4 位，日志里也不能打出完整 key。
- `.env` 里只放基础设施配置：数据库、Redis、MinIO 的连接信息，加密 key 用的主密钥，登录会话的签名密钥，以及初始管理员的用户名和密码。`.env` 不提交到代码仓库，仓库里放一份不含真实值的 `.env.example`。
- 后台改了模型配置后，新开始的生成任务立即使用新配置，正在跑的任务不受影响。

## 10. 网页

| 页面 | 内容 |
|------|------|
| 注册 | 用户名、密码、确认密码；提交后提示"等待管理员审核" |
| 登录 | 用户名密码登录；待审核或已停用的账号登录后只看到对应的提示页，不能使用其他功能 |
| 我的视频 | 这个老师的所有视频项目，显示状态（大纲待确认 / 生成中 / 已完成）和缩略图 |
| 新建视频 | 第 5 节的输入项 |
| 大纲编辑 | 按段列出标题、讲稿、画面方案、依据、内容性质、审核提示；可直接编辑或用一句话让 agent 改写；可增删段落、调整顺序；改过的段落有明显标记；底部是"生成视频"按钮 |
| 生成进度 | 每段的状态（排队 / 配音 / 画面 / 合成 / 完成 / 失败），失败的段可以单独重试 |
| 预览与下载 | 播放完整视频，也能按段跳转；下载 mp4；"回到大纲修改"按钮 |
| 我的偏好 | 列出 agent 记住的偏好，可以查看、修改、删除、手动添加（见第 12 节） |

大纲里的依据要能点开查看：上传素材显示原文片段，联网来源显示标题和链接。

**管理员后台**（只有管理员能进，草图见 `.superpowers/brainstorm/563-1792107763/content/admin.html`），分三个选项卡：

| 选项卡 | 内容 |
|--------|------|
| 页面配置 | "新建视频"页面每个选项一行：老师是否可见（开关）、默认值、可选值列表（可增删，比如增加科目、教材版本、时长档位）。"想讲什么"固定必填、不能隐藏。下方是"生成参数"，只有管理员能看到和修改：每段画面数范围、按时长的插图上限、同时生成的任务数、失败重试次数 |
| 模型配置 | 按用途各配一项：写大纲和讲稿、审核、看图识别、画插图、Embedding、配音、联网搜索。每项填接口地址、key、模型名，可以启用或停用，有"测试连接"按钮。配音一项还要维护音色列表（音色 ID、显示名称、试听），"新建视频"页的"配音声音"从这里取。某项必需的配置缺失或测试失败时，老师新建视频会看到"系统暂不可用，请联系管理员" |
| 用户管理 | 用户列表：用户名、角色、状态、注册时间、视频数量。可以审核通过或拒绝待审核的账号、停用和启用账号、重置密码、设为或取消管理员。有一个"开放注册"总开关 |

## 11. 账号、权限与数据隔离

- **注册**：用户名加密码。用户名不能重复；密码至少 8 位，用 bcrypt 或 argon2 加盐哈希存储。
- **账号状态**：待审核 → 正常；管理员也可以拒绝，或把正常账号停用。只有"正常"的账号能新建视频、调用任何会花钱的接口。停用账号已有的视频保留，不删除。
- **第一个管理员**：部署时由初始化脚本根据 `.env` 里的初始管理员用户名和密码创建，之后可以在后台把其他用户设为管理员。系统至少要保留一个正常状态的管理员，不能把最后一个管理员停用或降级。
- **登录安全**：同一用户名或同一 IP 连续登录失败多次后，暂时锁定一段时间。登录状态用带签名的会话 cookie（HttpOnly）。
- **数据隔离**：所有项目、素材、生成结果都归属到某个老师，每个接口都校验当前用户只能访问自己的数据。管理员后台只管理账号和配置，不提供查看其他老师视频内容的页面。MinIO 里的文件按老师分目录，通过有时效的链接访问。
- **权限**：管理员后台的所有接口在服务端校验管理员身份，不能只靠前端隐藏菜单。
- 第一版不做删除用户。

## 12. 记忆

记忆和业务数据都存在 PostgreSQL 里；Redis 只放队列、进度这类临时数据，不放记忆。

**短期记忆：一个视频项目之内**
- 内容：解析好的素材、找到的依据、当前大纲、审核结果、老师每一轮的修改指令，以及流程进行到哪一步。
- 存储：LangGraph checkpointer（`PostgresSaver`），每个视频项目对应一个 thread。老师确认大纲时流程暂停，状态落库；老师隔天回来，或者服务重启，都能从原来的位置继续。
- 状态以结构化的大纲和依据为主，不是一长串聊天记录。每个节点只读取它需要的部分，比如改第 3 段时只读第 3 段及其依据，这样修改多少轮，上下文都不会无限变长。

**长期记忆：同一个老师的不同项目之间**
- 内容：只存这个老师的偏好，比如"开场不超过 30 秒""多举生活中的例子""火柴人画风"，以及常用的科目、年级、教材版本。
- 存储：LangGraph Store（`PostgresStore`），按老师 ID 隔离。偏好多了以后需要按语义检索，再开启 pgvector 加 qwen embedding。
- 怎么记：老师修改大纲时，agent 发现某类修改反复出现，比如每次都把开场删短，就提示"要不要记住这个习惯"，老师确认后才保存。不在老师不知情的情况下记录任何东西。
- 怎么用：生成大纲和改写时，把这个老师的偏好作为要求一起交给模型；偏好和本次需求冲突时，以本次需求为准。
- **只存偏好，不存知识和史实。** 讲稿里的事实每次都必须重新从素材或联网来源找依据，不能因为"以前讲过"就直接复用。
- 老师在"我的偏好"页面可以查看、修改、删除、手动添加自己的偏好。管理员后台的"页面配置"里有一个开关，可以整体启用或关闭长期记忆。

## 13. 出错时怎么处理

- 大模型、图片、配音的接口调用失败时自动重试几次；还是失败，就把这一段标成"失败"并显示原因，其他段继续生成，老师可以单独重试这一段。
- 数学模板渲染失败（比如参数不合法），把错误信息交给大模型修正参数后重试；多次失败就标成"失败"。
- 后台服务重启后，没完成的任务可以接着做，已经生成好的段不用重做。

## 14. 我替你做的决定（可以改）

- 后台任务用 Celery。
- 第一版不用 Milvus；embedding 只在素材很长时用来挑选相关片段。
- 数学图形用 matplotlib 加预设模板，第一版不装 LaTeX、不用 Manim。
- 角色一致性靠"先生成角色参考图"来保证。
- 第一个管理员由部署脚本按 `.env` 创建；不能停用或降级最后一个管理员。
- 待审核的账号能登录，但只看到"等待审核"提示；忘记密码由管理员重置。
- 第一版只做停用账号，不做删除；管理员不能在后台查看其他老师的视频内容。
- 模型 key 存数据库并加密，`.env` 只放基础设施配置。
- 模型配置按用途拆成七项，每项都可以填同一个中转站。
- 后台增加"生成参数"（画面数、插图上限、并发数、重试次数），只对管理员可见。
- 长期记忆只存老师确认过的偏好，不存事实；管理员可以整体关闭长期记忆。
- 字幕默认烧进视频。
- 联网搜索默认开启。
- 关闭联网又没有素材依据时，用大模型自己的知识，并标成"未核实出处"。
- 视频时长允许约 ±15% 的偏差。
- 每次生成都保存版本，全部保留，可以恢复历史大纲。
- 合格来源的范围（第 7 节）：百科算次级来源，公众号、论坛不能单独作依据，冲突时以上传素材为准。
- 插图里不画文字，生成后用多模态模型检查。
- 英语课默认中文讲解、英文例句；多音字靠审核提醒加老师试听。
- 大纲生成后，尺寸和配音可直接改；科目、年级、教材版本、风格、时长、联网开关、素材一改就重新出大纲。
- 教材版本默认人教版，语文、历史、道德与法治默认统编版。
- 第一版代码模板覆盖的学科示意图种类（物理受力图、电路图、光路图、运动图像，化学结构式和方程式）。
- AI 画的地图不带国界和具体地名；需要准确地图时提醒老师上传标准地图。
