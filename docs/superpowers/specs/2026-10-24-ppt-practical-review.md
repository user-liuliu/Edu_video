# Practical PPT review policy
Approved in chat: outline knowledge checking precedes user confirmation; PPT review blocks only substantive errors.
- Preserve input -> outline approval -> preview and current frontend.
- Outline checks only knowledge, formulas, calculations, answers and conditions. Correct concrete errors with at most two repairs; show changes for user confirmation. Edits invalidate checking. Provider failures never pass.
- PPT blockers: wrong knowledge/formulas/graph meaning, severe unreadability, blank pages, invalid files. Color, spacing, decoration and slight wrapping are suggestions that permit preview/export without repair loops.
- Permit text/formula/practice pages without mandatory illustrations. Retain SVG security, resource limits and native editable export. Module bounding-box overlap alone does not prove unreadability.
- Preserve exact-content approval, previous decks, page isolation and partial delivery. Distinguish service/generation errors from content failures.
- Keep passed legacy approvals usable; new checks use the new policy. Metadata uses existing JSON; no schema migration.
- Test backend/frontend, build, render actual editable sample and integrate scoped files into the running software.
