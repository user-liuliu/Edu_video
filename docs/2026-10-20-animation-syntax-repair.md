# 动画脚本语法错误与修复上下文优化

## 故障与原因

《曹冲称象》第三版已保存 HTML 和六段系统配音，但生成脚本含 `SyntaxError: Unexpected token ')'`，整段脚本未执行。播放桥位于生成脚本之后，导致早期语法错误被次生错误“缺少 renderFrame”掩盖。自动修复再次发送完整大纲、设计参考与旧 HTML，上游响应失败，未产生可播放预览。另一个较早版本是在初次生成阶段触发网络总时限，不能与此语法故障混为一谈。

## 修复

- 在隔离渲染进程中用 Chromium CDP `Runtime.compileScript` 编译生成的经典脚本，不执行其内容，不访问外网；准确回传脚本序号、行列、HTML 行号和有限上下文。
- JSON 等数据脚本不作为 JavaScript 编译。既有确定性播放、倒退定位、音画校时和编码检查继续执行。
- 修复请求保留旧 HTML、冻结讲稿、逐句时间、画面要求、教师修改指令、素材 API 和风格；移除重复的原始大纲与 Skill 正文。初次创作仍加载设计参考。
- 不改动封存运行时摘要包含的文件，既有预览保持可读取、可验证。
- 继续使用已有有限修复次数和传输重试，不扩大网络时限，不增加视频内容 AI 审核，不重新调用配音模型。
- 整片编码检查另发现容器 CPU 配额为 2 核，但进程可见宿主机 12 核，FFmpeg 自动创建大量线程，连同浏览器触及 256 PID 配额并导致定位超时。渲染工作进程启动时按 cgroup CPU 配额约束自身 CPU affinity，子进程继承，避免过量线程；不改变媒体内容或运行时摘要。候选验证中 FFmpeg 线程从 81 降至 23，尚未触及 PID 上限。

本次实际修复请求由 66,200 字节减少到约 39,000 字节。

## 验证

- 最终后端全量：466 passed，3 skipped（环境缺少 Node 的既有跳过项）。
- 补充回归：14 passed，覆盖失败重试、有限修复次数、冻结配音及精简上下文。
- 隔离 Chromium：4 passed，覆盖原始语法错误定位、后续脚本语法错误、合法复杂脚本、数据脚本与仅编译不执行。
- 真实旧预览（155.33 秒）通过完整运行时采样检查，故障第三版准确定位为 script 1 / line 1 / column 18822。
- 候选镜像 `edu-video-backend:syntax-repair-20261020`、`edu-video-renderer:syntax-repair-20261020` 已部署，保留对应 before-syntax-repair 备份镜像。

整片 30 fps MP4 编码与全量解码检查成功：1280×720，155.333333 秒，4,509,828 字节，视频帧时长与音频一致。测试采用与生产相同的 2 核、2 GiB、256 PID 限制，`pids.events max 0`。渲染资源修复已部署，生产 PID 上限保持 256。验证产物不自动将教师项目标记为已导出。
